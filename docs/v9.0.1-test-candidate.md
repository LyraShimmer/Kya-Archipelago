# Kya Archipelago v9.0.1 RC2 — Local test candidate

Not published. Based on the user's `Kya-Archipelago-9.0.0-beta(3).zip`.
No GitHub mutation. Version numbers used in the AP handshake remain intentionally
at the 0.8.14 compatibility baseline to preserve 0.9.63 Launcher compatibility;
the seed's `logic_hotfix` identifies the RC2 logic revision.

## APWorld logic
- The six validated FT01 destinations open in AP Progression mode; YAML option
  `starting_fast_travels` removed. Vanilla mode retained.
- The false early Root shortcuts in AP mode are disabled.
- The Quarry's normal entrance and Wolfen 13 require Magic Bouncers.
- All 40 Wolfen City Wolfens and Map Discovery remain AP checks (41 total),
  with no progression rewards. Seventh locked bracelet is at Wind Tower 01.
- The Fortress checks remain AP checks but only accept filler/useful rewards,
  protecting against progression behind unverified endgame terrain.
- Shop bracelet accessibility uses the required prior Progressive Bracelet.
  No ROM/ISO or runtime shop-stock bypass is implemented.
- The six native Rune pickup checks remain safe (never hold progression).

## Launcher source patch: auto-credit vanilla Rune checks
On receiving a server-authoritative `Progressive Rune: ...` reward, the Launcher
now sends the counterpart vanilla Rune check automatically. This restores the
potential for 318/318 even though receiving the AP Rune sets the native pickup
flag and makes physical pickup unavailable. No game memory scan alone can
trigger this auto-credit; replay/reconnect checks are de-duplicated by durable
pending check and server acknowledgement. The game itself is not patched.

**Important:** The provided **Python source code** contains the new rune logic.
The user must rebuild the Windows Launcher EXE to use this new behavior in game.
The previous 0.9.63 EXE will still generate a valid AP connection and run but
will NOT automatically credit these Rune locations.
